# Native block geometry versus real browser observations (experimental)

This is the **first native-output observation bridge**, not an HTML/CSS
implementation or an application pilot. It joins a deliberately hand-resolved
tree in `grunkalunka-layout` to the separate Playwright reference collector.

The original block group in `native-block-bridge.html` avoids text,
percentage lengths, margin collapse, fonts and external assets. It measures
three block border rectangles. A second group now measures exact
definite percentage heights (described below). The independent Rust
example builds caller-resolved trees, asserts explicit rectangle goldens,
then emits a JSON receipt without parsing the HTML or CSS.

## Reproduce with a real browser

After fetching locked Rust dependencies and installing the optional Playwright
browsers (see `tools/browser-oracles/README.md`), run from the repo root:

```sh
mkdir -p target/browser-native-bridge
cargo run --locked --offline -p grunkalunka-layout --example native_block_bridge > target/browser-native-bridge/native.json
node tools/browser-oracles/collect.mjs --fixture=tests/browser-oracles/native-block-bridge.html --engine=all --output-dir=target/browser-native-bridge/captures
node tests/browser-oracles/native-block-bridge.mjs target/browser-native-bridge/native.json target/browser-native-bridge/captures/chromium.json
node tests/browser-oracles/native-block-bridge.mjs target/browser-native-bridge/native.json target/browser-native-bridge/captures/firefox.json
node tests/browser-oracles/native-block-bridge.mjs target/browser-native-bridge/native.json target/browser-native-bridge/captures/webkit.json
```

The bridge checks the exact local fixture SHA-256 against the collector receipt,
the fixed 800×600 CSS-pixel viewport at DPR 1, observation identities,
Playwright provenance and rectangle fields. It compares **only border
rectangles** and reports field-level differences without tolerance or
majority voting. Exit 0 means selected geometry matched, 1 means a measured
difference, and 2 means invalid/incompatible evidence or CLI failure.

The native sample is not generated by parsing the HTML or computing CSS.
The two inputs intentionally use independent code. Updating the fixture
requires reviewing its manually resolved counterpart and source tests.
A passing result cannot establish general block formatting, text/inline
layout, CSS cascade, paint, DOM events or standards conformance. The report
always says `conformance: not-assessed`.

The offline tests use synthetic browser receipts and do **not** establish
real-engine agreement. Native CI validates the example as a Rust target;
actual Blink/Gecko/WebKit comparisons require the commands above or a
separate hosted workflow. Never substitute synthetic captures for browser
evidence.
## Hosted three-engine evidence

The optional [native block bridge workflow](../.github/workflows/browser-native-bridge.yml)
executes the real Rust layout example once on Linux and uploads its unmodified
JSON output. Independent Chromium, Firefox and WebKit jobs download that
exact artifact, collect fresh Playwright observations of a retained HTML
snapshot, then run the geometry comparator against the Rust output.
An observed difference or incompatible source receipt fails its engine job;
the original captures, snapshot, native receipt and comparison reports are
retained even when differences occur. Version-pinned Playwright packages
and container-image identity match the main browser-smoke workflow.

This added real-engine evidence is a bounded box-layout comparison, not
general DOM/layout conformance or a replacement for cross-engine reports.
Changes in the native Rust engine or the fixture should therefore be reviewed
against the independent CSS/HTML expectations as well as the observed
browser coordinates.

## Shared validator and CI trigger coverage

The native comparator imports `tests/browser-oracles/compare.mjs` for
capture validation. The hosted native bridge workflow retriggers when that
shared file, `tools/browser-oracles/collect.mjs`, the pinned Playwright
package, its own fixture/tests/CLI, or its Rust layout inputs change.
Both PR and push filters use exact file paths and an audited layout subtree.

The `ci/impact/workflows/browser-native-bridge.json` descriptor
checks those source filters and key native/browser commands. It reports
**expected triggers only**, not verified hosted execution or success.
The Windows selective-CI gate still requires a complete canonical plan;
the independent browser workflows retain separate check conclusions.

## Native-to-browser visibility and reflow

The reference fixture now measures **three states**: the original fixed-size
block geometry, a live `display:none` mutation hiding the first child, and
restored geometry after removing the inline display override. The independent
Rust example recomputes the same parent-before-child tree for each state,
asserting literal goldens (including the parent shrinking from 86 to 40 px
and the following sibling moving upward from y=58 to y=12), and asserts full
frame equality after restoration. It does not cache or parse browser styles.

The browser collector preserves `reflow.hidden` and `reflow.restored` in its
original source-hashed receipt; it does not derive those values from the Rust
result. The bridge comparator rejects missing, incomplete, nonfinite or
unattributed state data rather than treating absence as no change. A hidden
node has **no box** (explicit JSON `null`), not an invented zero-sized
rectangle. Geometry and visibility differences identify the phase, node and
field. This remains a narrow selected-fixture test, not general DOM mutation,
CSS `display` conformance or browser rendering equivalence.

## Native hit-target comparison (next bounded slice)

The fixture additionally records seven fixed viewport sample points using
`document.elementFromPoint`, before hiding the first child, while it is
hidden, and after restoration. Only the three deliberately modeled element
IDs (`outer`, `first`, `second`) are reported; HTML/body/outside hits are
recorded as explicit `null`. This normalization is about the selected
comparison scope, not a claim that these outer ancestors are non-targetable.

The independent Rust example calls `grunkalunka_layout::hit_test` on each
recomputed frame using its explicit caller-selected targetable policy.
It asserts independent per-phase expected targets before emitting the
`hitTargets.original`, `hitTargets.hidden` and `hitTargets.restored` maps.
The comparator requires all seven named probes in all three phases, rejects
unknown/missing targets, and reports disagreements with probe/phase paths.
No hit is derived from browser rectangle observations or from source code
executed in the native runtime.

The selected probes distinguish child, parent, margin, sibling, off-box,
and restored hits; this does **not** implement DOM event dispatch, pointer
capture, CSS pointer-events, transforms, clipping, scroll-coordinate
translation, stacking contexts or trusted input events. The browser's DOM
hit testing and native target selection have only been compared for these
specific nonoverlapping, untransformed boxes.

## Real-engine negative control for geometry sensitivity

The hosted bridge workflow also runs a deliberately different, source-checked
reference fixture in each engine. After normal native-versus-browser agreement,
`native-bridge-sensitivity.mjs` changes exactly one reviewed CSS declaration:
`#first` has a content width of 101 px instead of 100 px. It writes a separate
read-only fixture snapshot and collects a **fresh real engine** capture.
The original Rust layout receipt remains unchanged; the comparison verifies
the capture's **mutated** source hash and expects **exactly two** geometry
differences: the original first-child border width and its restored width
must both be 119 CSS px instead of 118. The hidden first box stays absent.

This negative control is **intentional cross-source disagreement**, not a
normal conformance comparison, and never modifies or repairs browser receipts.
An unchanged observation, missing geometry difference, stale source hash,
extra discrepancy or malformed evidence fails the engine's CI job. Both raw
fixture bytes, original mutated capture and complete report are retained.
The independent baseline comparison continues to require exact agreement.

## Selected DOM hit-target negative control

The hosted bridge also varies *input targetability* without changing the
manually resolved native layout or any CSS dimensions. The independent
`native-hit-sensitivity.mjs` tool adds `pointer-events: none` to the
fixture's single `#first` rule, captures a **fresh real browser instance**
and checks source SHA-256 provenance against those changed HTML bytes.

The native fixture remains unchanged and continues to treat `first` as
targetable. Exactly six mismatches are required: `first-center`,
`first-lower` and `first-right` in both original and restored phases must
switch from the native `first` to browser `outer`. The hidden phase and
all measured rectangles must remain unchanged. Unexpected geometry,
invalid source hashes, missing target observations or extra differences
fail the check. Source copies, raw captures and full reports are retained.

This is a **sensitivity control**, not a claim that the native engine
implements CSS `pointer-events` or general DOM hit-testing semantics.

## Hosted assertions as ordinary tests

The browser jobs now run
`node --test tools/browser-oracles/hosted/native-bridge.test.mjs`
with the selected engine, original Rust receipt and new evidence directory
supplied explicitly by the host. The test itself checks real browser/native
parity, then executes the independent width, hit-target and percentage-height sensitivity tools
and retains all their reports. GitHub Actions remains responsible only for
the pinned browser environment, layout-only Rust artifact, and evidence upload.
The independent Node regression contracts run in the canonical offline suite,
not again inside each browser job. This adds no checks to the existing matrix.

## Real-engine percentage-height geometry witness

The independent source-checked native bridge now retains a **second block
group** after the existing original/reflow/hit-target fixture. The second
group has a definite 80 CSS-pixel containing content height with padding,
border and a top margin; its two children request `height: 50%` and
`height: 25%`. The reference HTML measures their actual browser
`getBoundingClientRect()` results in a separate `percentageHeights`
map. No browser rectangle is inferred from the nominal CSS dimensions.

The native Rust example constructs another **caller-resolved** block tree
rather than parsing the HTML or reading the browser's measurements. It
asserts independently chosen border-rectangle goldens for the parent and
both percentage-height children. The existing comparator now requires
three complete, finite named rectangles in both sources and checks every
coordinate/size exactly. A missing or malformed map fails closed; a
difference is identified independently of the earlier three-box reflow
and hit-target observations.

The same Chromium, Firefox and WebKit hosted jobs execute this comparison
and retain their raw fixture and capture artifacts. Existing CSS width
and pointer-events mutation controls still require exactly their original
differences; unintentional changes to the new height boxes also fail.
The native implementation supports **integral, definite height inputs only**.
This selected parity witness does not exercise CSS subpixel sizing,
height-percentages under indefinite parents, margin-collapsing edge cases,
general CSS formatting, or a native DOM/HTML parser.

## Real-engine negative control for percentage-height sensitivity

The hosted native bridge now includes a third independent mutation tool,
`tools/browser-oracles/native-height-sensitivity.mjs`. It copies the original
HTML fixture and changes exactly one reviewed CSS declaration on the
definite-height child: `#height-first` goes from `height: 50%` to
`height: 60%` under its unchanged 80 CSS-pixel containing content box.
The tool collects a **fresh** Chromium/Firefox/WebKit observation from those
modified bytes while retaining the original Rust receipt.

The comparator validates the mutated fixture's own SHA-256 provenance before
expecting exactly two differences. `height-first`'s border-box height changes
from 46 to 54 CSS pixels, and `height-second`'s border-box y position
changes from 156 to 164. The parent box, original three-box geometry,
hide/restore measurements, hit targets, and every other percentage-height
coordinate must remain unchanged. Missing or extra differences, incompatible
source hashes, invalid receipts or a changed mutation site fail the test.

The existing hosted `node:test` suite owns all three real-engine sensitivity
controls; the GitHub workflow still handles only environment, artifact transport
and the same three-engine matrix. Offline regression tests verify exact mutation
bytes and discrepancy shape but do not substitute for the live browser
observations. This is an intentionally wrong reference-source experiment,
not new CSS parsing or general percentage-height conformance.

## Source-checked global viewport scrolling

The bridge also includes one independent document-level scroll and hit-target
comparison. An offscreen target is measured using real browser
`window.scrollTo`, `getBoundingClientRect` and `elementFromPoint` before,
during and after restoring a 350px viewport scroll. The native sample
separately calls `hit_test_scrolled` on reviewed caller-resolved geometry;
the comparator requires exact offset, document extent, rectangle and target
observations. See the [viewport-scroll evidence guide](browser-native-viewport-scroll-bridge.md)
for goldens, source receipts and deliberately excluded browser behavior.

## Source-checked inherited visibility

A separate three-phase witness records normal-flow geometry, actual

## Real-engine descendant padding-box clipping

A separate source-checked `descendantClipStates` channel measures real DOM

and after disabling `overflow: clip` on a fixed-height block in the existing
scroll spacer. The independent native sample uses the caller-resolved
`DescendantClip::PaddingBox` policy and checks the unchanged original

## Boxless display:contents geometry and input

A separate three-phase source-checked witness measures real DOM
`display: contents` and `display: block` toggles, including wrapper
principal-box presence, child/sibling rectangles and actual input targets.
The Rust sample independently lays out the same caller-resolved tree,
without parsing CSS. The [boxless reference guide](browser-native-boxless-bridge.md)

## Inherited pointer-events: none / auto

The native/browser comparison now includes a three-phase source-checked
pointer-events witness. A parent with `pointer-events:none` remains
unhittable while an explicitly `auto` child can still be targeted;
changing the parent's policy to `auto` restores hits on the parent and
its inherited child without altering any rectangles. Independent Rust
`Frame::pointer_events` and DOM `elementFromPoint` receipts are
compared exactly. See the
[pointer-events evidence guide](browser-native-pointer-events-bridge.md).

## Source-checked horizontal auto-margin geometry and input

An independent three-phase `autoMarginStates` channel checks real CSS
centering and one-sided horizontal auto margins, a max-constrained auto
width, used margin values, and eight hit targets before, during and
after changing a real inline margin declaration. The Rust layout example
independently asserts integer-pixel rectangles and used margins;
`browser-native-bridge.yml` compares these with source-checked Chromium,
Firefox and WebKit receipts. See the
[auto-margin witness guide](browser-native-auto-margin-bridge.md)
for fixed coordinates, fail-closed schema and scope limits.

## Relative positive offsets without sibling reflow

A three-phase source-checked `relativeStates` witness compares actual
`position:relative` CSS left/top values, parent/child rectangles,
a normal-flow sibling and seven browser hit targets before, during and
after changing the parent's horizontal offset. The independent Rust
layout example preserves the sibling's normal position while shifting
the parent and nested child for paint/hit geometry. See the
[relative-position evidence guide](browser-native-relative-bridge.md)
for goldens, limits, fixture provenance and replay.
